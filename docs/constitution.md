# Constitución — Conecta UNMSM

1. Especificar antes de desarrollar: constitución → spec EARS → plan → tareas → pruebas.
2. Enfoque: oportunidades académicas reales con fuente (OCGRI, VRAP, VRIP y convocatorias de facultades), apoyos de bienestar, clínica y transporte.
3. Los 20 nombres de facultad no autorizan atribuir convocatorias indiscriminadamente. Cada servicio tiene público, alcance, fecha y fuente propia.
4. Un anuncio en un sitio académico **no significa** que la convocatoria esté abierta ni que exista beca, financiamiento o vacante.
5. Scraping automático descubre, pero no publica: revisar datos y aprobar la incorporación manual a Supabase. Respetar robots, acceso, límites y procedencia.
6. Gemini selecciona IDs permitidos; el servidor ensambla hechos documentados. Nunca dar diagnósticos, plazos/cupos inventados o permisos inferidos.
7. Consulta pública opcional, historial voluntario y mínimo; nunca almacenar el texto libre del estudiante ni contraseñas fuera de Supabase Auth.
8. La app prioriza seguridad, RLS, pruebas verificables, mensajes honestos de fallos, accesibilidad y español en UI.
9. Monolito modular FastAPI + HTML/CSS/JS + Gemini + Repository Supabase/JSON verificado; sin nuevas dependencias innecesarias.
10. Se puede estudiar y probar en laboratorio, pero los permisos del concurso gobiernan el uso de código preparatorio.
